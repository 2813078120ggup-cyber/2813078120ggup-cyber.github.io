本篇要点

  • 为什么用 RAG，以及 RAG 的基本准备 / 检索流程
  • 项目准备阶段 7 个节点、检索阶段 7 个节点的作用与意义

项目总览

项目阶段 ≈ Python 基础阶段，不用过多去理解，更多的去写、去敲——键盘敲烂，月薪过 3 万。

整篇总结分为五块：项目核心流程（RAG 扩展 + 准备 7 节点 + 检索 7 节点）、项目核心技术点清单、项目相关面试、使用 AI 生成页面的基本流程、后续安排。

1、项目核心流程

1.1 RAG 流程的扩展

1.1.1 为什么使用 RAG

现在的模型上下文窗口已经巨大了，为什么还要用 RAG？

  1. 模型窗口大小：每次真的使用都会消耗 token，内容过多反而不准确了。
  2. 模型某些方面有知识欠缺：不会的也会答，也就是幻觉。

1.1.2 RAG 的基本流程

1.2 项目准备阶段（7 个节点）

1.2.1 节点 1：node_entry

  • 核心作用：导入文件类型的识别判断，跳转到对应合适的解析节点（依赖 state）。
  • 意义：后续扩展文件类型时，需要扩展此节点的语法判断。

1.2.2 节点 2：node_pdf_to_md

  • 核心作用：将 PDF 类型的数据转成 md 数据。表面的含义是——把非结构化的数据，转成结构化的文本。
  • 意义：ppt / word / excel / json / 图片…… 扩展多了之后，统一转成结构化的文本（md / json）。

1.2.3 节点 3：node_md_img

  • 核心作用：处理图片，识别图片的含义，进行图片地址的上传（http）。
  • 意义：图片内容的识别。

**面试题：**你的 RAG 是做图文混合检索的么？
是——图片 -> [文本] -> 模型；图片 - http - 用户可视化显示……

  • 意义：图片 / 表格（数据）-> 单独处理 -> 数据库存储 -> 问题 -> llm -> sql -> 数据库表格数据查询，也就是自然语言处理数据库的数据检索（问数）。

1.2.4 节点 4：node_document_split

  • 核心作用：将 document 切成合理的 chunk。
  • 意义：避免过多的内容给到模型，干扰模型的回答。
  • 意义：目标是最合适的 chunk 送给最合适的问题。
  • 原则：
  1. 语义优先。# 标题、法律条件、财报、对话。
  2. 确保大小合适。500 - 1200，需要考虑嵌入式模型、重排序模型大小、文件类型。
  3. 边界清晰，保持合理的 overlap。
  4. 保留可追溯的元数据：item_name、title 等。

项目切割参数：400 / 600 / 1000。

1.2.5 节点 5：node_item_name_recognition

  • 核心作用：主体识别，小范围确认搜索对应的文档。
  • 意义：锁定范围，item_name / file_title / 时间。

1.2.6 节点 6：chunks 的向量化

对切好的 chunks 做向量化处理。

1.2.7 节点 7：chunks 的向量存储

将向量结果写入向量库，供检索阶段使用。

1.3 项目检索阶段（7 个节点）

1.3.1 节点 1：node_item_name_confirm

  • 核心作用：item_name 意图识别和问题重写。
  • 意义（问题重写）：用户的问题往往口语化、非专业化、带代词，直接进行向量查询会结果不存在；因此要做问题重写标准化，明确的主体、标准的提问，避免过多的口语。
  • 意义（item_name）：缩小范围。通过 llm - milvus 做置信度识别，阈值 0.7 / 0.6。
  • 阈值说明：0.7？满分 1 -> 满分 0.2……

1.3.2 节点 2：召回 1 —— 问题向量检索

  • 缺点：问题的语义单一，检索命中降低（召回率低）。

1.3.3 节点 3：召回 2 —— 问题假设性答案检索

  • 优点：丰富检索语义，提高命中率和召回率。
  • 缺点：文档类型极其隐私，因此通过降低权重减少影响。

1.3.4 节点 4：召回 3 —— MCP 网络检索

  • 优点：弥补单一向量库的内容缺失，是对文档内容的一种补充。

1.3.5 节点 5：node_rrf

自己融合，同源，融合召回 1 与召回 2；有参照、排名 + 权重。

1.3.6 节点 6：node_reranker

  1. 凑齐 [[问题, 答案]] -> 过长需要压缩，512 - 4。
  2. 打分。
  3. 动态 topk。

1.3.7 节点 7：node_answer

  1. 之前 answer。
  2. 本次模型 answer。
  3. 正则提取 image_urls。

2、项目核心技术点

2.1 RAG 思想

RAG 的整体思想：准备阶段的向量化 + 存储，检索阶段的多路召回 + 融合 + 重排 + 生成。

**遗憾：**没有智能体，也没有递归切割器。

2.9 视觉模型

4、使用 AI 生成页面的基本流程

  1. 明确需求和功能。
  2. 设计接口（api）：url、method、参数、响应。
  3. 接口和需求文档设计页面的原型图。
  4. 原型图、接口文档、需求文档设计项目页面（明确添加对应接口的交互流程）。
  5. 样式调整即可。

举个例子：进销存系统 = 进货 + 销售，就好比你家有个大超市——胖东来。
