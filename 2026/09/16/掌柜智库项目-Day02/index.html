在项目骨架上定义 ImportGraphState 状态与 12 个属性，梳理节点与业务分层、搭建 LangGraph 主图，并实现 node_entry 与 node_pdf_to_md 两个节点。

本篇要点

  • 定义导入图的 state：ImportGraphState(TypedDict) 与 12 个属性
  • 分清”节点层”与”业务层”的职责，掌握节点统一写法
  • 搭建 LangGraph 主图结构（builder -> add_node -> 条件边 -> compile）
  • 实现任务分发节点 node_entry
  • 实现 PDF 解析节点 node_pdf_to_md，顺带回顾 HTTP 协议与 requests

内容回顾

1、环境搭建

  • 使用 uv 管理项目：安装 uv、配置清华镜像、uv init --bare 初始化项目、uv venv --python=3.11 创建 .venv、pycharm 手动指定解释器。
  • 用 uv sync 同步依赖（pyproject.toml + uv.lock），再用 uv tree 校验依赖树。

2、项目骨架

  • 搭好了 app/ 下的 utils/shared、process、rag、resources、api、infra、tests 包结构。
  • 导入了公共类代码：.env、logger（node_log / step_log）、配置加载类、InfraConfig 等。
  • 用 .ignore 插件创建 .gitignore，项目接入 git 并完成第一次提交。

1.2 定义导入图的状态

  • ImportGraphState 继承 TypedDict，是整个导入图在节点之间流转的共享状态。
  • 属性的作用分两类：一类是节点之间要传递的数据（如 task_id、各类文件路径），一类是控制流程走向的开关（如 is_md_read_enabled、is_pdf_read_enabled）。

  • create_default_state 用深 copy 配合 dict.update 生成一份默认状态，避免多个任务共用同一个 dict 造成相互污染。
  • get_default_state() 直接拿到默认状态，省去每次手写初始化。

回顾：网络请求 requests 包的使用

  • 作用：在我们代码里可以调用外部的 api 接口，例如访问 MinerU -> url；requests 可以发起 http 协议的网络请求。
  • 介绍：hyper text transfer protocol 协议，用于客户端和服务器的通信网络协议。
    • 超文本： 超越文本类型的数据传递（不仅仅能传字符，更能传递字节，如图片、压缩包…）
    • 传输： 客户端 - 服务端
    • 协议： 规定传递数据格式

http 协议的数据格式（请求报文 | 响应报文）：

请求方式：

  • 字节数据、隐私数据、大于 2kb 的字符（浏览器对 url 的长度有限制）-> post / put
  • url、method：GET / POST / PUT / DELETE … 代表客户端对服务端的数据操作动作行为！
    • 查询 -> get
    • 保存 -> post（restful 基于 http 协议”最”标准的使用方案，提出 restful 的人就是 http 协议的主要发明人）
    • 更新 -> put
    • 删除 -> delete
  • url -> 指向服务端的资源 -> 名词，url 配合请求方式决定对资源的动作：
    • 根据 id 删除用户：错误 /user/remove?id=1，正确 /user/1 + delete
    • 根据 id 查询用户：错误 /user/find?id=1，正确 /user/1 + get

注意： 请求方式一定不要选错！不能选择无法传递数据的方式类型！

  • get 客户端想要获取、delete 想要删除 -> 请求行 url?key=value&..、请求头、没有请求体
  • post 想要上传、put 想要更新 -> 请求行 url?key=value&..、请求头、请求空行、请求体（字符 / 字节…）

对比举例：

  • 客户端 -> 上传头像（图片、字节、流）-> 服务端：post | put
  • 客户端 -> 登录账号（账号密码、字符）-> 服务端：post | put，不会选择 get / delete
  • 删除 id=1：user/delete?id=1...

响应报文结构：

使用流程：1. 获取状态码 == 成功；2. 获取响应体的数据 …

响应状态码：

  • 1xx 中继状态：101、102 … 请求还在继续，没有完成
  • 2xx 成功状态：200 完整请求成功；202 断点请求成功 -> 王者荣耀（20% 继续下载：读取本地下载的进度 -> 请求头 -> 服务端 -> 服务端只返回剩余的部分）
  • 3xx 重定向：304 我们访问目标服务器 -> 服务器将请求转到其他的服务器进行处理 -> 对于第一次请求已经是成功！间接成功
  • 4xx 客户端访问资源出现问题：404 资源未找到（url 地址错误）、405 请求方式异常、400 参数错误【对于客户端来说致命，不需要尝试】
  • 5xx 服务器内部异常：500 -> 代码异常抛出，又没有捕捉到 -> 客户端
