掌柜智库项目 Day 01｜RAG 理解与项目环境搭建

发表于2026-09-14|更新于2026-10-16|开发掌柜智库项目
|总字数:1.8k|阅读时长:6分钟|浏览量:

从 RAG 的基本原理讲起，完整记录 uv 包管理工具的安装与镜像配置、项目基本包结构搭建、公共类代码导入与首次 Git 提交。

本篇要点

  • 理解 RAG 的基本流程，明确项目为什么用 RAG
  • 掌握 uv 的安装、镜像配置、项目初始化与依赖同步
  • 搭建项目的基本包结构，导入项目公共类代码
  • 把项目交给 git 管理并完成第一次提交

内容回顾

1、为什么使用 RAG

  • 现在模型的上下文窗口已经巨大了，但每次真的使用都会消耗 token；塞进去过多的内容，回答反而不准确了。
  • 模型在某些方面有知识欠缺，不会也答（幻觉）。

2、RAG 的两条链路

  • 准备：各种数据文件 -> text -> 嵌入式模型 -> 向量 -> 向量数据库
  • 检索：用户提问 -> 嵌入式模型 -> 向量 -> 相似度 -> chunk -> 问题 + 上下文 -> 提示词 -> LLM -> 结果
  • 掌柜智库项目的整条流程，就是这条 RAG 流程的工程化扩展：准备阶段 7 个节点、检索阶段 7 个节点，后面每天实现其中一部分。

1.4 同步项目依赖

需要共享两个文件：

  • pyproject.toml -> 项目信息、依赖信息（很多都不是固定的版本，是范围版本）、镜像信息
  • uv.lock -> 记录下载时刻的具体版本，作用是避免依赖同步版本漂移！

uv sync 想要同步所有依赖配置（下载）时，会先检查 pyproject.toml 的依赖信息（范围版本），再检查 uv.lock 中具体的版本，最后进行下载。

同步项目配置的步骤：

  1. 找到 掌柜智库 / 资料 / 依赖配置 这 2 个文件
  2. 粘贴到当前项目下，适当修改项目基本信息（项目名）
  3. 执行 uv sync 进行依赖同步
  4. 校验：uv tree 看见依赖树
  5. 校验：创建 xx.py，写 from langchain ... 能导入成功（导入失败一般是解释器选择的不对）

2、搭建项目的基本架构

2.1 搭建项目的基本包结构

说明：

  • process 放 langgraph 的节点，rag 放核心业务代码，两者都按 import_ / query 分目录，和项目”准备 / 检索”两条链路一一对应。
  • api 分成 http（接口）和 schema（数据类型）；infra 是对外统一的公共出口。
  • utils / shared 是工具模块，像 minio、mongodb、milvus 这些原则上不需要我们自己写。
