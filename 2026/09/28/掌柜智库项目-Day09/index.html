1.1 单列检索

  • 注重语义 → 用稠密向量。
  • 注重关键字命中 → 用稀疏向量。

1.2 混合检索

混合检索其实是单列检索的升级版本：根据一个实体的多种状态进行搜索，最终确定目标。比如搜索一种动物，通过它的外观、声音、肤色来共同确定。

混合检索常用的两种模式：

  1. 多模态搜索：对一行数据的多个字段进行搜索（外观、声音、肤色）。
  2. 稠密和稀疏向量：对一行数据的一个字段生成稠密和稀疏向量进行匹配。

混合检索的语法分三步：

第一步：创建 AnnSearchRequest

可以把每个 AnnSearchRequest 理解为一路检索。

第二步：配置 Rerankers 策略

Reranker 是把多路结果合并到一起的规则和策略，milvus 提供的策略有两种：

3、节点 node_search_embedding_hyde

作用： 让问题（rewritten_query）先经过大模型获取答案，再用“问题 + 答案”的向量与数据库 chunks 的 content（item_name + title + content）向量做相似度比较，获取匹配的切块。

HyDE 的核心思路：

4.1 MCP 是什么

  • mcp = Model Context Protocol，模型上下文协议，是一套标准和规范。

  • MCP 的作用：基于 mcp 标准的服务端和客户端可以共享 tools / resources / prompt 提示词。

  • 对比 skill：

    对比项 MCP Skill
    相同点 都是提升 agent 的能力 都在提升 agent 的能力
    侧重维度 代码维度 提示词和业务点
    不同点 通过网络调用获得服务端提供的代码 文件的加载

4.2 MCP 常用的具体协议

MCP 服务端 = 调用 = MCP 客户端（我们这边，如何调用服务端）。

MCP 是一个概念，真正调用要靠具体的技术：

  • stdio：本地协议调用（同一个电脑上的 server 与 client），本质是进程通信，非常少见。
  • sse：网络协议调用（服务端 URL 网络地址）。
  • streamablehttp：是 sse 的升级版本，网络连接更轻、性能更好。

4.3 MCP 的使用方式

方案一：硬编码

调用关系是：我们 -> 客户端 -> 加载 -> 1 2 3 -> 不同的 mcp server。这种方式不推荐。

方案二：框架实现（Adapter）

思路是把“多个 server 分别加载”收敛成“一种方式统一加载”：

适配器 1：langchain 的适配器。

缺点：只能给 langchain.create_agent 提供。

适配器 2：OpenAI 提供的 mcp 处理适配器。

方式 1：给 OpenAI 方式创建的智能体配置工具。

方式 2：设计了更普遍的工具调用方式（不是智能体 / langgraph 图，而是自己代码调用 tool）。

小结一下本节要点：

  • MCP 是什么？tool / resources / prompt。
  • MCP 和 skill 的异同点？能力扩展，一个偏代码、一个偏提示词与业务。
  • MCP 具体的使用协议：stdio、sse、streamable_http。
  • MCP 具体的使用：① 硬编码（不同协议不同的加载方式）；② 适配器（langchain | openai 提供）。
