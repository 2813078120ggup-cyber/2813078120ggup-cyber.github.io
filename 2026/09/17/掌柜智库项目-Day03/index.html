掌柜智库项目 Day 03｜图片处理节点与 MinIO 对象存储

发表于2026-09-17|更新于2026-10-16|开发掌柜智库项目
|总字数:3.2k|阅读时长:12分钟|浏览量:

实现图片处理节点 node_md_img，用视觉模型识别图片内容、上传 MinIO 替换为网络地址，并完成对象存储与 LLM 的 infra 封装。

本篇要点

  • 梳理当前图的节点状态，明确图片处理要解决的问题
  • 实现 node_md_img：scan_images 取图片上下文 → 视觉模型 summarize_images → 上传 MinIO 并替换 md 内容
  • 掌握 MinIO 的 docker 部署、可视化操作、桶权限 policy 与 Python 增删查
  • 用 MinioGateway 与 LLMProvider 把对象存储和模型能力封装进 infra
  • 回顾正则：re.escape、search/match/findall/finditer、贪婪与非贪婪

内容回顾

1、上一天主题（Day02）

  • 定义 ImportGraphState(TypedDict)，共 12 个属性，配套 create_default_state / get_default_state
  • 节点与业务分层：@node_log 装饰器 + add_running_task / add_done_task
  • 主图构建：builder → add_node → set_entry_point → 条件边 → compile
  • 任务分发节点 node_entry，PDF 解析节点 node_pdf_to_md（MinerU 上传/轮询/下载解压重命名）

2、基础工具小结

  • Path 属性：.name、.stem、.suffix、.parent、.parents
  • Path 方法：.is_dir、.exists、.mk_dir、.read_text、.read_bytes、write_text、write_bytes、.rename、.with_name、.rglob、.glob
  • shutil 方法：rmtree(文件夹)、unpack_archive(解压的文件, 目标文件夹)、make_archive("压缩文件名","压缩格式",压缩文件或者文件夹地址)
  • requests：请求用 requests.get/post/put/delete(url, headers, params, json, data, timeout)；响应用 .status_code、.json()、.text、.content，以及 requests.Session()
  • MinerU 的使用：申请上传地址和 batch_id（POST）→ 向指定的预签名地址请求 → 轮询获取响应结果

2、node 中的图片处理

2.1 节点作用

将 md 中的图片进行处理：

这样处理有两方面优势：

  • 优势一：让图片真正参与到内容回答中（图片内容会被模型识别）。对应面试/追问点：你们的 RAG 是做的图文混合检索的么？
  • 优势二：本地地址换成网络地址，客户端在任何位置都可以访问和回显图片，回答问题的时候可以直接带上图片。

2.2 参数说明

  • 使用：md_path → md_content → images（图片文件夹）
  • 生成：md_content；文件由 文件名.md → 文件名_new.md

2.3 准备工作

  • 准备文件服务器 / 文件服务器的使用
    • 自己搭建：minio 搭建文件服务器（需要考虑服务器、搭建维护成本）
    • 直接买：阿里、腾讯、华为等 OSS 对象存储服务器（需要花钱）
  • 准备视觉模型对象
  • 在 infra 层封装：minio 的操作 | 模型的使用

2.4 实现步骤总览

  1. 安装了 minio 软件
  2. 准备 minio 的公共类（桶名、图片前缀、client、构建访问路径）
  3. 准备 llm 的公共类（获取大语言模型 / 获取视觉模型）
  4. 获取数据并且校验（state → md_path）→ md_content、images_path_obj、md_path_obj
  5. 判断 images 文件夹是否为空
  6. 为后续步骤做准备，提取图片的信息：每张图片 → (图片名.jpg, 图片地址, (上文, 下文))
  7. 使用视觉模型进行图片的意图识别
  8. 将图片传递到 minio，并且完成 md_content 内容的替换
  9. 替换 state 内容 md_content、md_path

6、step 8：上传 MinIO 并替换 md_content

实现细节：

  1. 获取 minio 客户端对象
  2. 先删除当前文件图片（minio 上的）
  3. 循环 image_context_list 向 minio 上传文件 → dict[str: image_name, str: 网络地址]
  4. 循环”图片 → 网络地址”对应的字典，逐一替换 md_content 内容
  5. 返回 md_content_new

细节（面试/坑）：

  1. 查询 prefix 不能以 / 开头（处理方式 [1:]）
  2. 查询到的对象要转成 DeleteObject，即 [DeleteObject(o.object_name) ...]
  3. 删除 errors：for ... yield
  4. 上传用 fput(bucket_name, object_name, file_path, content_type=guess_type[0])
  5. 拼接访问地址
  6. 替换：md_content = re.sub(lambda _: f"![]()", md_content)

7、step 9：回写 state

  • 把 md_content 备份到原文件名对应的 文件名_new.md 文件中
  • 替换 state 中的 md_content、md_path

8.2 可视化操作和使用（minio 的核心概念）

  1. 访问 minio 客户端：ip : 9001
  2. 登录和认证：minioadmin / minioadmin
  3. 创建一个桶：一个项目对应一个桶
  4. 上传文件或者文件夹，桶内结构例如：

  1. 访问地址规则

    • minio 部署的时候可以添加 ssl 证书（安全）
    • 地址格式：http | https → 端点 + 桶 + 桶内全路径（对象名）
    • 例如 http://ip:9000/0318tong/mv.jpg、http://ip:9000/0318tong/images/mv.jpg

  2. 拒绝访问问题

    • minio 文件服务器默认：上传需要认证（登录），访问也需要认证（直接访问会被拒绝）
    • 解决思路：1）访问时添加认证；2）修改桶权限——上传需要认证，但访问可以匿名

要点小结：

  • re.escape() 用来转义图片名中的字面字符（如 demo(1).png 的括号），避免被当成元字符
  • search 找第一个、match 只从开头、findall 返回字符串列表、finditer 返回 Match 对象
  • Match 对象可通过 .group()、.start()、.end()、.span() 获取内容与位置
  • .* 贪婪、.*? 非贪婪，图片语法必须用非贪婪避免跨越多个图片
