3.4 索引

单列索引：常用于查询的条件列，设置索引可以提高查询效率。

选 1 还是 -1 呢？随便！凭感觉！

复合索引：用于条件查询 + 排序场景。

例如：查询 session_id 对应的历史会话前 20 条。

为什么复合索引适合「条件查询 + 排序」场景？因为复合索引根据第一列进行排序，第二列在第一列的基础上再进行排序。也就是说，第二列以后不具备单独提高查询效率的能力了，只有在满足第一列的条件下，才能快速定位到结果。

面试题：为什么有索引就能提高查询效率？为啥不把所有的字段都设置索引？

索引是一种额外的数据结构！脱离原始数据存储顺序，是更高效搜索的数据（红黑树等，logN）。索引需要占有磁盘或者内存空间！不常用的字段设置了，会浪费空间。

5、node_item_name_confirm 节点

5.1 作用

识别 item_names（提问 / 历史上下文），并把 original 重写成 rewritten...。有可能 item_name 识别不到（1. 分低；2. 完全没识别）。

5.2 参数

使用（读取）：

  • session_id -> 获取用户的聊天记录
  • original_query -> 原始问题
  • is_stream

生成（写入）：

  • item_names
  • rewritten_query
  • answer（可能）

5.3 实现步骤

步骤 1：获取并且校验参数（state）-> session_id / original_query

步骤 2：获取（有效的）历史聊天记录，并且拼接成 history_text 提示词

步骤 3：调用模型识别 item_names 和 rewritten_query -> json（item_names 不一定准，大模型）

面试题：怎么确保大语言模型返回的数据是 JSON 格式？

  1. 提示词强调返回数据格式，提供返回数据示例
  2. 模型的 json 模式设置
  3. 做好返回值的参数校验 JsonOutputParser ``` json -> json dict
  4. 返回字典 key 的校验：item_names 无 -> []；rewritten_query 无 -> original_query

步骤 4：item_names 进行向量检索（item_name）对应的 collection -> [item_names milvus 分高 / 分低]

步骤 5：置信度判断 milvus -> 分 -> 可信的列表 | 不可信的列表

步骤 6： 没有识别 -> answer；识别了但分不高 -> answer -> state answer…；识别出来且分高 -> state [item_names / rewritten_query]

步骤 7：保存本次提问的历史对话（item_names / rewritten_query），并相应 return。
