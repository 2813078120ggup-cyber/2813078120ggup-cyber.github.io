2、查询模块图结构定义

查询模块的图一共规划了 8 个节点，先回顾每个节点的作用、读取与写入的 state 字段。

2.1 用户提问

用户提问是整个流程的起点。

2.2 意图识别和问题重写节点

  • 意图识别：由「问题 + 历史聊天记录」确定 item_name，结果分三种：
    1. 明确的 item_name（向量数据库搜索相似度分高于 0.75）
    2. 不确定的 item_name（相似度分没有达到 0.75，落在 0.75 - 0.6 之间）
    3. 完全不确定 item_name（没有高于 0.6 分）
  • 问题重写：把「他好用么？」改成「烫金机好用么？」——口语化、没有主语的问题要改成标准的问题，利用模型 + 历史聊天记录完成。

该节点读写字段：

  • 读 original_query：用户原始问题，例如「他好吃么？？」
  • 读 history：历史对话记录，用于上下文理解（history 历史记录来自数据库）
  • 读 session_id：会话追踪。一个客户端一个 session，每次问题不并发！
  • 写 item_names：识别出的商品名称列表（确认的实体名称）
  • 写 rewritten_query：改写后的精准问题
  • 写 answer：如果无法确认或需要反问，直接写入答案并提前结束流程

2.3 问题向量搜索

重写后的问题 -> 向量数据库。

  • 读 rewritten_query：改写后的问题进行向量检索
  • 读 item_names：限定检索范围（只在这些商品内搜索）
  • 读 session_id：任务追踪
  • 写 embedding_chunks：普通向量检索回来的 Top-K 切片

2.4 假设性问题向量搜索

重写后的问题 -> LLM -> 润色出一个初版本的答案，再用「问题 + 答案」去向量数据库搜索。

  • 读 rewritten_query：生成假设性答案的原材料
  • 读 item_names：限定检索范围
  • 读 session_id：任务追踪
  • 写 hyde_embedding_chunks：HyDE 策略检索回来的切片

2.5 mcp 网络信息搜索

问题 -> mcp[模型上下文协议] -> bailian 提供网络搜索工具 -> 网络数据搜索。

  • 读 rewritten_query：网络搜索的查询词
  • 读 session_id：任务追踪
  • 写 web_search_docs：联网搜索返回的文档列表

2.6 同源数据融合

问题搜索和假设性问题搜索各 10 条 -> 向量数据库 10 条 -> 用 rrf 算法融合成 10 条。

  • 读 embedding_chunks：向量检索结果
  • 读 hyde_embedding_chunks：HyDE 检索结果
  • 读 session_id：任务追踪
  • 写 rrf_chunks：RRF 融合排序后的统一列表

2.7 非同源进行模型打分 + 动态 topk 算法

rrf 10 条 + mcp 10 条 -> reranker 打分 20 条 -> 动态 topk => topk 数据。

  • 读 rrf_chunks：待重排的文档列表
  • 读 web_search_docs：网络搜索结果
  • 读 rewritten_query：用于计算相关性得分
  • 读 session_id：任务追踪
  • 写 reranked_docs：重排序后的最终 Top-K 文档

2.8 进行数据的格式化处理

模型进行润色 + 图片的处理 + 前端的响应。

  • 读 reranked_docs：作为 LLM 回答的参考依据
  • 读 rewritten_query：用户问题
  • 读 history：历史对话
  • 读 session_id / is_stream：控制输出方式
  • 写 answer：最终生成的答案
  • 写 image_urls：从引用文档中提取的图片链接

task_util：

sse_util：

  1. 把 task_push_queue(session_id)（来自 task_util）真正地放在货架上，queue == push_to_session
  2. 属性：_session_stream: Dict[str, queue.Queue] = {session_id, 队列}
  3. 方法：
    • get_sse_queue(session_id: str)：根据 session_id 获取队列（不需要我们调用）
    • push_to_session(session_id, event, data)：stream_queue.put({"event": event, "data": data})
    • remove_sse_queue(session_id: str)：清空队列！每次提问执行之前先清空！
    • create_sse_queue(session_id: str)：创建队列，每次提问都需要创建一次队列！[每次调用]
